# Git 노선도

## ▶ [여기를 눌러 바로 열기](https://abback-go.github.io/GitMap/)

Git의 브랜치가 어떻게 갈라지고 다시 합쳐지는지를 **지하철 노선도**로 보여줍니다.
설치할 것도, 가입할 것도 없습니다. 링크를 열고 버튼만 누르면 됩니다.

> 커밋은 **역**, 브랜치는 **노선**, 병합 커밋은 두 노선이 만나는 **환승역**입니다.

명지전문대 AI게임학과 강의 자료입니다.

## 처음이라면

오른쪽 위 **▶ 자동 안내**를 누르세요. 설명 말풍선이 따라다니며 커밋부터 브랜치 · 병합 ·
원격 저장소까지 직접 시연해 줍니다. 그냥 두면 저절로 넘어가고, `이전` · `다음`으로
원하는 속도로 볼 수 있습니다.

25단계가 세 장으로 나뉘어 있습니다.

| 장 | 내용 |
|---|---|
| 1부 · 혼자서 시작하기 | 커밋 · 브랜치 · 서버에 올려두기 |
| 2부 · 팀과 주고받기 | 팀원의 커밋 · fetch · pull · PR 병합 |
| 3부 · 정리 | 기호 · 로그 · 시나리오 비교 |

말풍선 아래 **진행 막대의 칸을 누르면 그 단계로 바로 건너뜁니다.** 주소 끝에
`#step=12`처럼 붙여 열면 그 단계부터 시작하므로, 중간에 끊겼을 때 이어보기 좋습니다.

한 바퀴 돌고 나면 **자유 모드**에서 직접 눌러보세요.
잘못 눌러도 `한 단계 되돌리기`와 `처음부터`가 있으니 마음껏 망가뜨려도 됩니다.

## 화면 보는 법

| 영역 | 무엇을 보나 |
|---|---|
| 가운데 노선도 | 버튼을 누를 때마다 선로가 그려집니다 |
| 노선도 위쪽 (내 컴퓨터) | 내 커밋과 브랜치 |
| 노선도 아래 회색 띠 (팀 공용 서버) | **내 컴퓨터가 마지막으로 확인한** 서버 위치 |
| 현재 위치 (HEAD) | 지금 내가 올라타 있는 브랜치 |
| 명령 | 커밋 · 브랜치 만들기 · 이동 · 병합 · 리베이스 |
| 원격 저장소 (origin) | 팀원이 커밋 · 가져오기(fetch) · 받아오기(pull) · 올리기(push) |
| 실행한 명령 | **진짜 터미널에 칠 git 명령**이 쌓입니다 |

노선도가 가로줄로 **두 구역**으로 나뉘는 게 핵심입니다. 위는 내 컴퓨터, 아래 띠는 팀이
함께 쓰는 서버입니다. `push` · `fetch` · `pull`은 이 경계를 넘나드는 동작입니다.

띠에 있는 `origin/main` 이름표는 **서버의 현재 위치가 아니라 내가 마지막 `fetch`로
확인한 위치**입니다. 서버에만 생긴 새 커밋은 흐린 역으로 그려지고, `fetch`를 해야
이름표가 거기까지 따라옵니다.

마지막 칸이 핵심입니다. 여기 쌓인 명령을 그대로 Git Bash에 옮겨 치면 같은 결과가 나옵니다.
버튼 조작과 실제 명령을 짝지어 익히세요.

맨 위 흐린 두 줄(`git init`, `git remote add origin`)은 **저장소를 만들 때 한 번만** 치는
것이고, 그 아래가 작업할 때마다 반복되는 명령입니다. `git add`(담기)와 `git commit`(저장)이
항상 짝으로 나오는 것도 눈여겨보세요 — 담지 않은 변경은 커밋되지 않습니다.

## 기호 읽는 법

| 기호 | 뜻 |
|---|---|
| 빈 동그라미 | 보통 커밋 |
| 가운데가 찬 동그라미 | 병합 커밋 (부모가 둘인 유일한 커밋) |
| 회색 점선 동그라미 | rebase 후 버려진 옛 커밋 |
| 진회색 점선 동그라미 | 서버에는 있지만 아직 `fetch`하지 않은 역 |
| 분홍 `HEAD` | 지금 올라타 있는 브랜치 이름표를 가리킴 |
| 속이 빈 이름표 | 서버 띠에 있는 원격 위치 (`origin/main` 등) |

## 이걸로 알 수 있는 것

- 커밋은 지우는 게 아니라 **쌓이는 기록**이라는 것
- `HEAD → 브랜치 이름표 → 커밋`의 3단 구조. 브랜치를 옮기면 HEAD가 이름표 사이를 이동합니다
- 브랜치를 만든다는 건 **같은 역에 이름표를 하나 더 붙이는 것**일 뿐이라는 것
- 병합 커밋이 생기는 경우와, 새 역 없이 미끄러져 가는 `fast-forward`
- rebase는 커밋을 **복사**해서 해시가 바뀌고, 옛 커밋이 점선으로 남는다는 것
- 원격 저장소: `git push`로 올리고 `git pull`로 받아오는 흐름
- **`fetch`와 `pull`의 차이** — `fetch`는 가져오기만 하고 내 브랜치를 움직이지 않습니다. `pull`은 `fetch` + `merge`
- `origin/main` 이름표는 **서버의 현재 위치가 아니라 내가 마지막으로 확인한 위치**라는 것
- 새로 만든 브랜치는 `git push -u`로 올려야 서버에 생긴다는 것
- `push`가 거절되는 상황과, **push한 브랜치에 rebase를 쓰면 안 되는 이유**

`시나리오 · Merge`와 `시나리오 · Rebase`를 차례로 돌려 보면
같은 상황을 두 방식으로 처리했을 때 무엇이 달라지는지 나란히 비교할 수 있습니다.
