# Git 노선도

Git의 브랜치가 어떻게 갈라지고 다시 합쳐지는지를 **지하철 노선도**에 빗대어 보여주는 교육용 웹앱입니다.
커밋은 **역**, 브랜치는 **노선**, 병합 커밋은 **환승역**입니다.

명지전문대 AI게임학과 강의 자료로 만들었습니다.

## 실행 방법

`git-branch-map.html` 파일을 브라우저로 열면 끝입니다. 설치도 서버도 필요 없습니다.

```bash
git clone https://github.com/abback-go/GitMap.git
```

내려받은 폴더에서 `git-branch-map.html`을 더블클릭하세요.

## 화면 구성

| 영역 | 내용 |
|---|---|
| 노선도 | 커밋 그래프. 버튼을 누를 때마다 선로가 그려집니다 |
| 현재 위치 (HEAD) | 지금 올라타 있는 브랜치 |
| 명령 | 커밋 · 브랜치 만들기 · 이동 · 병합 · 리베이스 |
| 원격 저장소 (origin) | 팀원이 커밋 · 받아오기(pull) · 올리기(push) |
| 실행한 명령 | 버튼 조작에 대응하는 **실제 git 명령**이 쌓입니다. 그대로 터미널에 옮겨 치면 같은 결과가 나옵니다 |

## 모드

- **자유 모드** — 직접 눌러가며 실험합니다. `한 단계 되돌리기`와 `처음부터`가 있어 마음껏 망가뜨려도 됩니다
- **시나리오 · Merge** — 기능 브랜치를 만들고 merge로 합치는 과정을 한 줄씩 실행
- **시나리오 · Rebase** — 같은 상황을 rebase로 처리. 해시가 바뀌고 옛 커밋이 점선으로 남는 걸 비교합니다
- **자동 안내** — 21단계 가이드 투어. 설명 말풍선과 스포트라이트가 따라다니며 직접 조작까지 시연합니다

## 다루는 개념

- 커밋이 쌓이는 방식과 해시
- HEAD → 브랜치 이름표 → 커밋의 3단 구조 (브랜치를 옮기면 HEAD 표시가 이름표 사이를 이동합니다)
- 브랜치 분기와 병합 커밋(부모가 둘인 유일한 커밋)
- fast-forward
- rebase가 커밋을 **복사**하며 해시를 바꾸는 것, 버려진 옛 커밋
- 원격 저장소: `origin/main`, push / pull, 병합 커밋을 만드는 pull
- push가 거절되는 상황(non-fast-forward)과 **push한 브랜치에 rebase를 쓰면 안 되는 이유**

## 읽는 법

| 기호 | 뜻 |
|---|---|
| 빈 동그라미 | 보통 커밋 |
| 가운데가 찬 동그라미 | 병합 커밋 |
| 점선 동그라미 | rebase 후 버려진 옛 커밋 |
| 분홍 `HEAD` | 지금 올라타 있는 브랜치 이름표를 가리킴 |
| 속이 빈 이름표 | 원격 저장소(`origin/main`)의 위치 |

## 기술 메모

- 의존성 없는 **단일 HTML 파일**입니다. 그래프는 SVG로 직접 그립니다
- 외부 자원은 Pretendard 웹폰트 CDN 하나뿐이며, 없어도 시스템 폰트로 동작합니다
- `localStorage` / `sessionStorage`를 쓰지 않습니다
- 데스크톱(1440px)과 모바일(390px) 양쪽에서 확인했습니다

`https://abback-go.github.io/GitMap/git-branch-map.html` 주소로 바로 열 수 있습니다.
